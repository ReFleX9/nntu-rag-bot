# Публичный сборщик сайта НГТУ

Скрипт обходит публичные HTML-страницы сайта НГТУ и скачивает документы, на которые
они ссылаются. Вход в учётные записи не выполняется; внешние домены не обходятся.
Для каждого HTML URL из `robots.txt` проверяется перед запросом. Стандартная
скорость — не более примерно одного запроса в секунду.

## Запуск в PowerShell

Из корня проекта:

```powershell
python -m pip install -r site_crawler/requirements.txt
python site_crawler/crawl_nntu.py --output data/nntu_site --verbose
```

По умолчанию обход начинается с главной, раздела для абитуриентов, расписания
студентов и страницы ЭИОС. Ссылки внутри сайта ведут краулер дальше, в том числе
в разделы меню «Образование» и «Жизнь в НГТУ». Ограничения по умолчанию: глубина 12
и до 5000 страниц; их можно изменить флагами `--max-depth` и `--max-pages`.
После остановки продолжить можно командой с `--resume`.

## Результат

- `pages.jsonl` — текст страницы, заголовок, URL, глубина, дата и ETag/Last-Modified.
- `pages/*.html` — исходная HTML-страница.
- `links.jsonl` — каждая гиперссылка: URL назначения, подпись, title, исходная
  страница и окружающий текст. Для ссылок внутри таблиц в `link_context` помещается
  текст всей строки (например, название ресурса, способ доступа и гиперссылка).
- `files.jsonl` и `files/` — скачанные файлы, тип, размер, SHA-256, исходная ссылка,
  подпись ссылки и контекст.
- `errors.jsonl` — сетевые ошибки и недоступные страницы/файлы.
- `crawl_summary.json` — сводка запуска.

Для RAG по умолчанию загружаются документы и таблицы, а не декоративные картинки,
скрипты и стили. Максимальный размер одного файла — 1024 MiB (`--max-file-mb`),
общий лимит хранилища — 50 GiB (`--max-total-gb`).
Картинки, загруженные в предыдущих прогонах старой версии, остаются в `files/`;
их можно отделить фильтром по `content_type` при последующей обработке.

`topics` — предварительные метки по простым ключевым словам (`admission`, `study`,
`campus_life`, `university`). Они нужны для отбора и не удаляют страницы/файлы.
При RAG отбирать лучше позже, используя метки вместе с URL, заголовком и содержимым.

## Тематическая витрина файлов

После сбора можно построить предварительные категории по именам, URL, подписи и
контексту ссылки:

```powershell
python site_crawler/categorize_corpus.py data/nntu_site --materialize-links
```

Скрипт сохраняет `classification.jsonl`, `classification.csv` и
`classification_report.md`. Папки `data/nntu_site/organized_view/` содержат hard
links на оригиналы из `files/`, поэтому не дублируют объем, но являются только
навигационной витриной. Категории предварительные; материалы с недостаточными
сигналами попадают в `99_неопределено_на_проверку`. После извлечения текста и OCR
классификацию стоит обновить.

## Область обхода

По умолчанию разрешён домен `nntu.ru` и его поддомены. Это включает переходы на
публичные поддомены НГТУ, если они находятся в ссылках, но не включает сторонние
сайты и файлы на них. Можно сузить область: `--domain www.nntu.ru`. Не обходятся
страницы, запрещённые `robots.txt`. Для первого полного сбора рекомендуется оставить
скорость по умолчанию; сайт может ограничить автоматические запросы.

Это первый этап сбора: содержимое файлов сохраняется как есть. Затем PDF можно
передать в `chanker`; для HTML использовать `pages.jsonl`, а XLS/XLSX и DOCX нужно
разбирать соответствующими загрузчиками. Публичность ссылки сама по себе не означает,
что файл актуален: год, семестр и дата проверки должны учитываться при индексации.
