# Аббревиатуры из всех PDF — версия 2

## Запуск в Jupyter

1. Распакуй архив в **новую папку**. Это не затронет прежние результаты.
2. Положи все 139 PDF в папку **pdfs** внутри неё. Можно сохранить вложенные папки продуктов.
3. Открой **RUN_ALL.ipynb** в Jupyter.
4. Выполни первую ячейку — установка библиотек. После установки при необходимости выбери **Kernel → Restart Kernel**.
5. Выполни ячейку **`%run start_all.py`** кнопкой ▶ или Shift + Enter.

Программа найдёт все PDF, включая вложенные папки и расширение `.PDF`. Фиксированного
лимита 139 нет. Модель загружается один раз, затем книги обрабатываются по очереди.
Текст каждой книги читается целиком для контекста, NER выполняется по страницам.

Папка **results_corpus** появится рядом с программой. Во время работы в ней хранится
прогресс. Итоговые CSV создаются в конце; при обычном прерывании сохраняется частичный
результат. После аварийного закрытия повтори ту же ячейку. Завершённые страницы не
обрабатываются заново. Не удаляй `progress.sqlite3`. Перед повторным экспортом
закрой CSV в Excel, если он блокирует их перезапись.

## Что получится

| Файл | Для чего |
| --- | --- |
| **abbreviations.csv** | Основная таблица: каждое найденное упоминание, частота по корпусу и документу, document_count, файл, страница, раздел, контекст. |
| **dictionary.csv** | Общий словарь: одна строка на ключ, частота, document_count, варианты написания, один пример с источником. |
| **documents.csv** | Одна строка на каждый PDF: охват страниц, находки, возможные сканы, ошибки, SHA-256 для обнаружения копий. |
| **TABLE_DESCRIPTION.txt** | Значение каждой колонки и правила подсчёта. Создаётся и в папке результатов. |
| **RUN_STATUS.txt** | Краткий итог: сколько документов завершено, сколько страниц требуют проверки. |
| mentions.jsonl | Все упоминания для дальнейшей обработки Python/RAG, включая точные позиции и исходные цитаты по страницам. |
| progress.sqlite3 | Текст страниц и сохранённый прогресс. |
| issues.json | Ошибки файлов/страниц и страницы для проверки OCR. |
| run.json | Настройки, версии библиотек, дата экспорта и полный/частичный статус. |

**В abbreviations.csv одна строка = одно упоминание.** Например, WAL в двух разных
местах имеет две строки с разными контекстами. `occurrences` — уже готовый итог по
всему корпусу; он повторяется в строках и его нельзя суммировать. Для общего словаря
открой dictionary.csv. Одинаковые ключи могут иметь разные значения; эти значения
не объединяются в одну подтверждённую расшифровку.

CSV: **UTF-8 с BOM**, разделитель **`;`**. В Excel при необходимости:
**Данные → Из текста/CSV → UTF-8 → разделитель «точка с запятой»**.
В Python: `pd.read_csv("results_corpus/abbreviations.csv", sep=";", encoding="utf-8-sig")`.
Для удобства Excel текст, начинающийся на знак формулы, получает защитный апостроф;
JSONL хранит текст без этого изменения.

## Контекст: 3 + 1 + 3 предложения

Сохраняются предложение с находкой, три полных предложения до него и три после.
Контекст может переходить через границы страниц **одного PDF**. В начале/конце книги
или возле недоступного текста предложений может быть меньше. Колонки
`sentences_before`, `sentences_after`, `context_status` показывают это явно.

Для предложений используется **razdel 0.5.0**: учитывает русскую пунктуацию,
распространённые сокращения и числа. Технические таблицы, код и списки не всегда
состоят из предложений, поэтому автоматическая сегментация может ошибаться.
Если в этом месте нет обычных предложений (например, запись глоссария), берётся
сам текстовый блок и до трёх соседних блоков с каждой стороны. Это явно отмечается
как `context_status=structured_text`; блоки не выдаются за полные предложения.
Переносы строк нормализуются пробелами. Крайние номера страниц и повторяющиеся
колонтитулы маскируются, кроме строк с найденными упоминаниями. Это эвристика,
а не универсальное восстановление вёрстки. Исходные цитаты с позициями сохраняются
в `context_fragments` JSONL и проверяются по тексту в SQLite.

**physical_page** — номер PDF-страницы с 1, включая обложку. **printed_page** — метка,
заданная внутри PDF издателем; без метки поле пустое. **section** определяется
закладками с точностью до страницы и может быть пустым. **product_family** берётся
из первой подпапки внутри pdfs.

## Библиотеки и модель

- **PyMuPDF** — текст страниц и закладки PDF.
- **transformers + PyTorch** — NER.
- **razdel** — границы предложений.
- **csv, sqlite3** — стандартные библиотеки Python для таблиц и прогресса.

Основная модель: `kaejo98/acronym-definition-detection`, закреплена версия
`24af86d7b264660f34806c045340c56c6f7a3e6a`.
Это специализированный детектор AC/LF на многоязычной XLM-RoBERTa. Обучение в
карточке указано на английском PLOD-filtered. Здесь сохраняются только AC.
Для числовых LABEL_0…4 используется явная карта BIO, проверенная в прежних тестах;
подробности в VALIDATION.md. В новой версии модель и фильтр находок не менялись.

Первое скачивание модели — примерно 1.1 GB, дополнительно нужны зависимости и
место для результатов. Инференс локальный. Python 3.11/3.12 подходят для комплекта.
При доступной CUDA выбирается GPU, иначе CPU. При нехватке памяти GPU размер батча
снижается. Совместимая сборка PyTorch выбирается по ОС, видеокарте и драйверу:
https://pytorch.org/get-started/locally/ . Проверки этого комплекта выполнялись на CPU.

Необязательная GLiNER ставится через requirements-gliner.txt. Это прежний вариант
для сравнения, запуск через PyTorch; ONNX Runtime не требуется.

## Дополнительные команды

Из Jupyter, из папки программы:

```python
# Все PDF с выбранной выходной папкой:
%run extract_abbreviations.py pdfs --output results_custom

# Только пересобрать таблицы из уже сохранённых данных, без NER:
%run extract_abbreviations.py pdfs --output results_custom --export-only

# Несколько NER-страниц твоего примера; текст книги читается целиком для контекста:
%run extract_abbreviations.py "pdfs/745d7c1dfcce_postgres-A4-fop.pdf" --pages 428,713,2730-2734 --output results_sample_v2
```

Из терминала заменяй `%run` на `python`. Флаг `--pages` нужен только для пробного
NER: по умолчанию обрабатываются все страницы. Экспорт всегда включает все
сохранённые находки из выходной папки. Пробный запуск отмечается как partial,
поскольку NER ещё не прошла остальные страницы.

Для других входных путей, моделей и порогов нужна отдельная папка результатов.
Прежняя версия 1 хранит другую структуру данных: не указывай её папку результатов
новой версии. Новая стандартная папка называется results_corpus.
Если PDF изменился, его прежние находки удаляются и файл обрабатывается заново.
Удалённые из входной папки PDF исключаются из следующего экспорта. Копии PDF с
разными путями учитываются отдельно; проверь одинаковые SHA-256 в documents.csv.

## Что значит качество результата

**Это словарь найденных кандидатов.** NER уже показывала и пропуски, и ложные
находки на примере Postgres. Счётчик означает «найдено моделью», а не гарантированно
все реальные появления сокращения. Расшифровка не выдумывается: expansion=null.
Для подтверждённого словаря terms.jsonl нужны отдельное извлечение расшифровок
и проверка на нескольких семействах документов.

Сканы требуют OCR — этот комплект его не выполняет. Ошибка одного PDF не
останавливает остальные. documents.csv и run.json позволяют проверить, что
обработаны все файлы, и увидеть незавершённые страницы. В CSV нет ограничения
длины контекста или числа строк под Excel; большие данные удобнее читать Python.
