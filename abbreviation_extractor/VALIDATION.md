# Проверка готового кода

Дата: 22 сентября 2026 года.

Реальные модели запускались локально на CPU, не через внешний inference API.
Вход: предоставленный PDF `745d7c1dfcce_postgres-A4-fop.pdf`, руководство
Postgres Pro Enterprise 9.6.24.1, 2763 физических страницы.
Проверены **7 страниц: 428, 713, 2730–2734**. Остальной PDF и ещё 138 PDF не прогонялись.

Это **число предсказаний, а не precision, recall или F1**. Полной ручной разметки
всех упоминаний и отрицательных примеров этих страниц не выполнено. По этой таблице
нельзя утверждать превосходство модели по точности на всём корпусе.

Специализированная модель выделила, например, СУБД, MVCC, SSI на физической
странице 428; WAL, ECC на странице 713; GiST и GIN на странице 2731.
Она также пропускает часть сокращений: например, при этой настройке не выделила
API на странице 2730 и WAL в словаре на странице 2734, хотя WAL в основном тексте
на странице 713 выделяется. Это конкретная причина не считать готовую модель
универсальным законченным решением без оценки и адаптации.

В сыром выводе встречались имена Postgres, Pro, Perl и обрывки букв. Добавленный
фильтр границ/формы удаляет такие случаи, но может снижать полноту на сокращениях
в нижнем регистре. Для аудита есть флаг `--keep-unfiltered`.

В новом `sample_results` находятся 68 ранее полученных предсказаний основной
модели, выгруженные в новый формат с предложениями из полного текста книги.
Это пример результата, не полный словарь корпуса.

## Особенность специализированного checkpoint

`kaejo98/acronym-definition-detection` сохраняет в config только LABEL_0…LABEL_4,
хотя в карточке перечислены BIO-типы сокращений и длинных форм. В коде явно задана
карта для конкретного закреплённого commit:

| Номер | Тип |
| ---: | --- |
| 0 | O |
| 1 | B-AC |
| 2 | I-AC |
| 3 | B-LF |
| 4 | I-LF |

Интерпретация карты основана на порядке меток в карточке автора и проверена на
контрольных предложениях с `smart contract (SC)`, `principal component analysis (PCA)`
и `natural language processing (NLP)`: первые слова длинных форм получили LABEL_3,
продолжения LABEL_4, сокращения LABEL_1, окружающий текст LABEL_0. LABEL_2 в этих
контрольных примерах не встретился; его трактовка как I-AC следует карточке автора.
Эта карта не переносится автоматически на произвольную другую модель.

Также обнаружено повторение B-AC на соседних частях одного слова: например, `MV`
и `CC`. Скрипт объединяет соприкасающиеся части, сохраняя точные границы исходного
текста; слова, разделённые пробелом, не объединяются этим правилом.
