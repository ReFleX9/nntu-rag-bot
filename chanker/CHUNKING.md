# Подготовка корпуса НГТУ к RAG

## Команды

Из корня проекта:

```powershell
python -X utf8 chanker/chunk_extracted_corpus.py
python -X utf8 chanker/audit_chunk_jsonl.py
```

Первый скрипт читает `data/nntu_site/extracted/blocks.jsonl` и `documents.jsonl`, а также категории из `data/nntu_site/classification.jsonl`. Результат — `data/nntu_site/extracted/chunks.jsonl`; сводка генерации — `chunking_report.json`. Второй скрипт потоково проверяет JSONL и пишет `chunking_audit.json`, не загружая весь корпус текста в память.

## Как формируются чанки

- PDF-страницы и архивные файлы остаются отдельными источниками; в чанке сохраняются документ, исходный путь, страница, категория, название, URL, OCR-статус и уверенность OCR.
- HTML режется примерно по 1,500 символов внутри страницы. Текстовые подписи ссылок остаются рядом с абсолютными URL НГТУ; повторяющиеся ссылки на странице схлопываются, управляющие `javascript:`-ссылки и cookie-баннеры исключаются.
- Поступление, материалы для студентов и административные документы используют бюджет около 1,750 символов; образовательные программы — 2,100; наука и сведения об университете — 2,300; прочие материалы — 2,000. Табличные строки группируются примерно до 1,800 символов.
- Для распознанных электронных таблиц сохраняются непустые значения ячеек и их исходные номера столбцов. Пустые строки исключаются; при неоднозначных/объединённых заголовках скрипт не приписывает значениям угаданные названия столбцов.
- Чанки не дублируют соседний текст. Вместо перекрытия в записи есть `prev_chunk_id` и `next_chunk_id`, чтобы этап извлечения ответа мог расширить контекст по исходному документу.
- `token_count` пока `null`: токены надо измерить выбранным токенизатором модели эмбеддингов, когда будет зафиксирована модель.

## OCR и исправление текста

Скрипт делает безопасную нормализацию Unicode и удаляет мягкие переносы, но не исправляет орфографию автоматически. Ошибки OCR помечаются уверенностью распознавания и `quality_flags`; сейчас чанки с низкой уверенностью и символом замены `�` требуют ручной проверки. Автокоррекция OCR может испортить ФИО, номера приказов, даты, коды направлений и суммы. Для значимых сканов правильный следующий шаг — сверка фрагментов с изображением страницы либо адресная повторная OCR-обработка.

## Текущий результат и ограничения

Текущий корпус содержит 258,769 чанков из 10,389 документов; медиана — 1,457 символов, 95-й перцентиль — 2,240, максимум — 2,300. Текущая генерация не вычисляет токены и не строит индекс. Точный повтор текста сохраняет все ссылки на источники; аудит насчитал около 63 тыс. повторных текстов, поэтому перед векторизацией полезно выполнить дедупликацию по хешу текста с сохранением списка источников.

Категории остаются в метаданных, а не в отдельных индексах: перед запуском чат-бота нужно решить, как ранжировать поступление/студенческие материалы и общую научную документацию. Некоторые Excel-файлы с объединёнными ячейками сохраняют позиции значений, но требуют отдельной визуальной сверки исходной книги перед использованием как точного табличного справочника.
